## 1. Academy identity

### Name
**OAE Online Academy**

### Short descriptor
**Learn to build, automate, and operate software with AI.**

### Positioning
OAE Online Academy is a practice-led learning environment for people who want to move beyond prompt-only AI use and learn structured AI-assisted engineering workflows.

### Mission
Help learners develop practical capability in AI-assisted software engineering, repository intelligence, automation, agentic workflows, testing, verification, and responsible deployment.

### Learning philosophy
**Understand → Plan → Build → Test → Verify → Explain → Improve**

Learners should leave each learning unit with something they can inspect, explain, test, or improve—not just a completed video.

### Audience
- Developers moving into AI-assisted engineering
- Technical founders and builders
- Automation specialists
- Product-minded engineers
- Students and early-career technologists
- Non-traditional builders who can work with basic Git, terminal, and web concepts

### Prerequisites
The academy should provide a beginner route. Advanced modules may assume:
- basic computer literacy
- basic Git/GitHub concepts
- willingness to work with a terminal
- ability to read simple code
- access to a development environment

No formal degree should be required unless a future programme explicitly adds such a requirement.

# 8. Standard lesson template

Every OAE Academy lesson should use this structure.

### 1. The problem
What real engineering problem does this lesson address?

### 2. The concept
Explain the idea in plain language.

### 3. The pattern
Show the reusable engineering pattern.

### 4. Worked example
Demonstrate the pattern on a small example.

### 5. Practice
Give the learner a bounded task.

### 6. Verification
Ask the learner what evidence would prove the work is correct.

### 7. Reflection
Ask:
- What changed?
- Why did it change?
- What could fail?
- How would you verify it?

### 8. Next step
Connect the lesson to the next practical task.

# 9. Learner project rubric

Use a 4-dimension internal review rubric. This is a learning rubric, not a professional certification.

| Dimension | Evidence |
|---|---|
| Understanding | Learner can explain the problem and approach |
| Engineering process | Requirements, plan, implementation and review are traceable |
| Verification | Tests/checks are appropriate and evidence is recorded |
| Communication | Learner can explain decisions, limitations and remaining risks |

Recommended feedback labels:
- Strong evidence
- Evidence developing
- Needs revision
- Human review required

Do not convert this rubric automatically into a credential or employment claim.

# 10. OAE AI Tutor configuration brief

### Tutor name
**OAE Study Assistant**

### Purpose
Help learners understand OAE Academy material, practise engineering reasoning, and prepare questions for human review.

### System behaviour

The tutor should:
- explain concepts clearly
- use examples
- ask clarifying questions
- guide learners toward verification
- distinguish facts from assumptions
- encourage learners to inspect generated code
- recommend tests
- explain errors
- point learners to the relevant lesson
- say when human review is needed

The tutor must not:
- impersonate a human instructor
- claim accreditation
- issue certificates or credentials
- grade high-stakes work
- alter learner records
- mark completion
- invent course policies
- invent documentation
- expose another learner's information
- request passwords, API keys, bank details, or secrets
- make consequential admissions, finance, employment, disciplinary, or safeguarding decisions

### Tutor response pattern

**Understand → Explain → Example → Practice → Verify → Escalate if needed**

### FAQ

**Do I need to be a professional developer?**  
No. The Foundations route is designed to establish the required concepts. Advanced courses progressively introduce more technical work.

**Is this only about prompting?**  
No. Prompting is one tool. The academy focuses on context, engineering process, testing, verification, and responsible AI-assisted development.

**Will AI build everything for me?**  
That is not the goal. You will learn to use AI as part of an engineering workflow while retaining responsibility for understanding, reviewing, and verifying the result.

**Are courses self-paced?**  
The initial learning design is asynchronous-first. Individual programmes can later be configured for live, blended, or supervised delivery.

**Do I receive a certificate?**  
Do not publish a certificate promise until the academy's credential policy, issuer identity, verification design, and applicable requirements have been separately reviewed and configured.

# 18. Launch states

NSOS should expose these states rather than pretending the academy is ready:

**DRAFT**  
Content is being prepared.

**INTERNAL REVIEW**  
Content exists but owner review is incomplete.

**STAGED**  
The academy has been configured in a controlled environment.

**READY FOR OWNER APPROVAL**  
Required internal checks are complete; owner decisions remain.

**PUBLISHED**  
Public content has been explicitly approved and published.

**OPEN FOR ENROLMENT**  
Admissions and any required payment workflow have independently passed their gates.

The academy must never infer a later state from content existence alone.
